# pgvector + tsvector Strategy

Yes, **Supabase supports both `pgvector` and `tsvector`**, allowing you to perform **semantic search**, **keyword search**, and **hybrid search** directly within your PostgreSQL database.

## 1. pgvector (Semantic Search)
pgvector is an open-source PostgreSQL extension enabled in Supabase that adds support for **vector data types** and **similarity search**. It is used to store and query AI embeddings (high-dimensional float arrays).

*   **Purpose**: Semantic search (search by meaning).
*   **Setup**: Enabled via the Database > Extensions menu or SQL: `create extension if not exists vector;`.
*   **Capabilities**:
    *   Native `vector` column type (supports up to 16,000 dimensions).
    *   Indexing algorithms: **HNSW** (fast approximate search) and **IVFFlat** (memory-efficient).
    *   Distance operators: Cosine distance, L2/Euclidean, and Inner Product.
*   **Use Case**: Storing embeddings generated by models like OpenAI or Claude to find documents with similar meanings.

## 2. tsvector (Keyword Search)
**`tsvector`** is a native PostgreSQL data type (no extra extension required) used for **full-text search**. Supabase leverages this for traditional keyword matching.

*   **Purpose**: Keyword search (search by exact words or stems).
*   **Setup**: Built into Postgres; typically used with a generated column: `to_tsvector('english', content)`.
*   **Capabilities**:
    *   Tokenization and stemming (e.g., matching "running" to "run").
    *   Ranked results based on term frequency.
    *   Indexed using **GIN** (Generalized Inverted Index) for performance.
*   **Use Case**: Finding documents containing specific terms or phrases.

## 3. Hybrid Search (Combining Both)
Because both technologies run inside the same PostgreSQL instance, Supabase allows you to combine them into a **hybrid search** query. This merges the relevance of semantic matching with the precision of keyword filtering.

*   **Implementation**: You can execute a query that calculates scores for both `tsvector` (keyword) and `pgvector` (semantic) matches, then combines them (often using Reciprocal Rank Fusion) to return a unified result set.
*   **Benefit**: Enables filtering vector results by specific metadata or keywords while maintaining semantic understanding.

## Hybrid Search (The Real Power)

```sql
WITH semantic AS (
  SELECT id, 1.0 / (rank + 1) AS score FROM articles
  ORDER BY embedding <=> $query_vec LIMIT 50
),
keyword AS (
  SELECT id, ts_rank_cd(search_vector, query) AS score
  FROM articles, plainto_tsquery('english', $query) query
  WHERE search_vector @@ query LIMIT 50
)
SELECT id, COALESCE(s.score * 0.7, 0) + COALESCE(k.score * 0.3, 0) AS final_score
FROM semantic s FULL JOIN keyword k USING (id)
GROUP BY id ORDER BY final_score DESC LIMIT 20;
```

This gives you:
- **Precision** of keyword matching (exact terms, entities, quotes)
- **Recall** of semantic matching (synonyms, paraphrases, cross-lingual)
- Single query, single round-trip, PostgreSQL-native
