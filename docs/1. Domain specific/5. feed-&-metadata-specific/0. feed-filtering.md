## 1. Overview & Objective

The **Infinite Feed & Analytical Filters** form the core user interface of the Global News Aggregator. Instead of simple category buttons, the feed implements a robust, state-preserving infinite scroll with specialized 3-axis filters designed to track geopolitical bias, country perspectives, and regional news dynamics.

### The 3-Axis Geopolitical Filter Architecture
To allow deep analysis of narratives, news is classified along three distinct axes:

1. **`Event Region` (What is the news about?):** The geographical subject of the article (e.g., Middle East, Asia-Pacific). Extracted dynamically via Stage 1 Gazetteer or AI.
2. **`Source Origin` (Where is the publisher based?):** The macro region / geopolitical base of the news outlet (e.g., Russia is Europe, Al Jazeera is Middle East). *Note: Derived dynamically from sourceCountry.*
3. **`Source Type` (What kind of publisher is it?):** The editorial structure (e.g., *State Media, Independent Wire, Commercial Publisher, Amplifier/Aggregator*).

*Example Use Case:* An analyst can filter the feed to show articles covering the **Middle East** (`Event Region`) reported by **State Media** (`Source Type`) based in **Europe** (`Source Origin`), showing exact soft-power narrative angles.

### Scope Boundaries
- **Cursor-Based Infinite Scroll:** Avoids offsets to prevent skipped or duplicated items when new articles are ingested in real-time.
- **URL-Driven Filters:** All navigation state (search, category, sorting) lives in the URL, enabling instant shareability and standard browser back/forward navigation.

## 3. Research & Decision Matrix

### Dimensional Falsification Matrix

| Candidate Solution | Efficacy & Determinism | Operational Cost / Latency | Complexity / Debt | Outcome / Verdict |
| :--- | :--- | :--- | :--- | :--- |
| **Option A: Offset-Based Pagination** (`LIMIT Y OFFSET X`) | ❌ **Low** (Row positions shift constantly as new RSS crawls occur, causing duplicates/skips in feed) |  **Low** (Simple DB query) |  **Low** (Standard framework setup) | **Disproven** (Unstable on real-time feeds) |
| **Option B: Cursor-Based Pagination** (`take: Y + 1, cursor: { id: lastSeenId }`) |  **High** (Completely stable. Points to a specific anchor ID and scrolls relative to it) |  **Low** (Saves SQL execution plans; doesn't scan entire tables) | ⚠️ **Medium** (Requires tracking tiebreakers if timestamps match) | **Accepted** (Current Implementation) |

## 4. Technical Architecture & Data Model

The pagination architecture operates via hybrid React Server Components (RSC) and Client Components to deliver instant First Contentful Paint (FCP) while maintaining smooth infinite scroll.

```
layout.tsx (Static HTML shell)
  └── <Suspense fallback={<FeedSkeleton />}>
        page.tsx (Reads searchParams at request time, queries first 20 articles)
          └── ArticleFeed.tsx (Client component; mounts initial 20 articles, listens to scroll)
                ├── IntersectionObserver (Sentinels trigger fetch page + 1)
                └── URL Query Syncer (Sorts, filters, search writes)
```

### Pagination Implementation details
- **Take + 1 Trick:** We fetch `TAKE + 1` (21) rows. If 21 items return, we know a next page exists. The `nextCursor` is set to the 20th item's ID. If 20 or fewer return, `nextCursor` becomes `null`.
- **Unique Tiebreaker:** Prisma query ordering always appends `{ id: "asc" }` to prevent paging ambiguity if multiple articles share an identical `publishedAt` timestamp.

- **`< md` (< 768px):** Mobile sidebar is hidden (accessible via Sheet drawer). Feed takes full width.

- **`lg → xl` (1024px - 1280px):** Sidebar is full size (224px).
- **`xl+` (≥ 1280px):** Sidebar is full size. Left feed occupies center, and the right panel (288px) displays Analytics widgets.
