## 1. Overview & Objective

The **Admin Dashboard** provides the administrative control center and system observability dashboard for the Global News Aggregator. It allows admins to manage RSS feed sources, monitor system health, inspect error logs, track API token usage, manage user accounts, and override AI models or prompt profiles dynamically to manage run costs.

### Objectives
- **Feed Observability:** Audit which RSS crawling jobs are active, when they last succeeded, and which are failing.
- **Resource Control:** Toggle models, adjust prompts, or pause pipeline stages to control API token expenses.
- **Diagnostics:** Provide real-time logging views showing whether crawler pipelines or topic scanners are stuck, overlapping, or throwing errors.

### Scope Boundaries
- **Exclusively Server-Protected:** Admin route (`/system-supar-admin`) is blocked at layout level from non-admin accounts.
- **Non-Realtime Diagnostics:** System log updates will read from cached database logs rather than maintaining a WebSocket connection.
---

### Proposed Process Flow (Telemetry & Overrides)
1. **Settings Cache:** Ingestion workers load `SystemSetting` overrides (e.g. `PAUSE_PIPELINE = true`) on startup and check cache every 5 minutes.
2. **Usage Logger:** All AI API calls (Groq, Gemini) log token metrics to the `AiUsage` table. The dashboard reads this table to build cost donut charts.
3. **Task Heartbeats:** Background tasks (rss ingester, topic scanners) write a timestamped heartbeat to `SystemSetting` (e.g. `{ "task": "scanners", "lastRun": "timestamp", "status": "running" }`). The Admin UI polls this to show current background activity.

## 5. Implementation Notes & Reference Guide

### Planned Layout Components
The admin dashboard `/system-supar-admin` will feature five main tabs:

1. **Source Control:**
   - Grid listing all `FeedSource` definitions with active toggles.
   - Form to add new feeds, prompting the admin for: `Name`, `URL`, `Source Country`, `Source Type`, `Bias Group`, and `Coverage Scope` (forcing alignment with 3-axis filters).
   - Display indicators showing the last check time and cumulative fetch failures (flagging dead links).
2. **AI Settings & Usage:**
   - Sliders to adjust fallback limits, switch primary models (e.g. Groq vs Gemini), or edit AI prompt templates.
   - **Per-Provider Tokenization View:** Displays active settings for primary and fallback providers: `tokenMultiplier`, `maxArticleTokens`, `maxRequestTokens`, and `reservedOutputTokens` (helps monitor/tune prompt truncation and rate-limit pacing).
   - Cost Telemetry: Line charts plotting tokens used and cost estimates over the last 30 days.
3. **User Management:**
   - List of all registered user emails, roles (Admin vs User), and a ban/suspend button.
4. **Diagnostics & Health:**
   - Real-time display showing worker heartbeats (Ingestion & Topic Scanners).
   - Error Feed: A collapsible text box displaying recent backend failure logs.
   - **Scraper Health Check:** Detect and flag any RSS scraper that returns 0 articles for 3 consecutive days (indicating a broken site structure or blocked IP). Provide an alert to update the Cheerio/Puppeteer selectors.
5. **Skipped Articles & Gazetteer Tuning:**
   - **Diagnostic Table:** Lists all raw articles currently classified as `"other"` (skipped from Stage 2 ML). Displays: `Title`, `Source`, `Snippet`, `Fetch Date`, and `Retention Count-down` (days left of the 30-day window).
   - **Tuning Sandbox / Add Gazetteer Term:** Allows the admin to click on keywords from a skipped article snippet and instantly append them to `gazetteer.json` for one of the valid categories.
   - **Action Buttons:**
     - **Force Re-categorize:** Change the category from `"other"` to a valid category and trigger Stage 2 ML processing for that article immediately.
     - **Extend Retention (Pin):** Mark the article's `clusterStatus` as `"SKIPPED_PINNED"` to exempt it from the daily 30-day auto-purge (useful for building test suites or rule benchmarks).
     - **Force Delete:** Delete the raw article and its skipped record from the database immediately to free up space.
6. **Failed Enrichments & Retries:**
   - **Failed Enrichment Table:** Displays all processed articles stuck in `FAILED_ENRICHMENT` status. Displays the raw article title, source, the fallback model used, and the error type (API timeout/rate-limit vs. JSON parse failure).
   - **Queue Controls:**
     - **Retry Selected:** Force the ingestion backlog script to process the selected raw articles again immediately.
     - **Discard Failure:** Update status to `ARCHIVED_UNENRICHED` to hide the failure from the active retry queue without deleting the raw article.
