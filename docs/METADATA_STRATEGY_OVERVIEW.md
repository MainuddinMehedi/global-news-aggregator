# Metadata Strategy & Geopolitical Intelligence Overview

This document explains the conceptual framework behind the metadata used in the Global News Aggregator. It serves as a guide for how data is structured to enable advanced geopolitical aggregation, clustering, and narrative analysis.

To build a true geopolitical monitor (and not just a generic RSS reader), the system must understand the difference between **What happened** and **Who is telling the story**. The metadata is the engine that makes this distinction possible.

## The Two Groups of Metadata

We split the metadata into two distinct groups: the static identity of the publisher, and the dynamic intelligence of the event.

### Group A: "Who is talking?" (The Publisher Identity)
*These fields are static. They are configured manually in `feeds.js` when a new RSS source is added.*

1. **`sourceCountry`** (e.g., *Russia, USA, Qatar*) → The exact physical location of the publisher.
2. **`sourceOrigin`** (e.g., *Europe, North America, Middle East*) → The macro geopolitical bloc.
3. **`sourceType`** (e.g., *State Media, Commercial Publisher, Think Tank*) → Who pays the bills. This dictates underlying motives.
4. **`biasGroup`** (e.g., *State-Aligned, Left-leaning, Centrist*) → The ideological lens they apply to events.
5. **`coverageScope`** (e.g., *Global, Regional, Local*) → Do they have reporters worldwide, or are they a local paper?

### Group B: "What are they talking about?" (The Event Intelligence)
*These fields are dynamic. They are generated by the NLP/AI enrichment pipeline for every single article.*

1. **`eventRegion`** → Where the event actually took place (e.g., *Middle East*).
2. **`categories`** → The topic (e.g., *Geopolitics, Economy*).
3. **`entities`** → Specific actors involved (e.g., *UN, USA, Iran*).
4. **`sentimentScore`** → The emotional tone of the reporting (-1.0 to +1.0).
5. **`clusterRef`** → The overarching "Story" this article belongs to.

## How the System Connects the Dots

By combining Group A and Group B, the system performs powerful geopolitical aggregation:

### 1. The "Perspective Gap" Discovery
Imagine an event happens: A trade dispute between China and Australia.
- The pipeline reads 5 articles and groups them into one **Story Cluster** because they share the same `entities` (China, Australia) and `eventRegion` (Asia-Pacific).
- The system then looks at Group A metadata to build the analytics widgets.
- It notices an article with `sourceOrigin: North America` and `biasGroup: Centrist` has a positive sentiment regarding Australia.
- It notices an article with `sourceOrigin: Asia-Pacific`, `sourceCountry: China`, and `sourceType: State Media` has a highly negative sentiment regarding Australia.
- **The Result:** The system automatically presents the user with a dashboard showing exactly how the Western narrative differs from the Chinese State narrative on the exact same event.

### 2. Advanced Analyst Filtering
Because this metadata exists, a user can use UI filters to ask highly specific geopolitical questions:
- *"Show me all news about the `eventRegion: Middle East` but ONLY written by publishers with a `sourceOrigin: Europe`."* (How does Europe view the Middle East?)
- *"Show me all `category: Economy` news, filtered to only show `sourceType: State Media`."* (What are foreign governments officially saying about the global economy?)

### 3. Algorithmic Balancing
If you just fetch "Top News", your feed might be 90% Western commercial media. The analytics widgets use `biasGroup` and `sourceOrigin` to calculate a pie chart of the current feed. If it sees that 80% of the articles on the screen are from North America, it visually alerts the user to an "echo chamber."

## Required Frontend Improvements: UX & Discovery Hierarchy (Tracking)

To fully utilize this metadata strategy, we must carefully design the user experience (UX) to make discovery both convenient and impactful. We must balance **"What are they talking about"** (Primary topics) with **"Who is talking"** (The geopolitical perspective).

### 1. The UX Discovery Hierarchy (Filter Placement)

Not all filters deserve the same real estate. The goal is to surface the most impactful discovery cues immediately, while keeping advanced analytical tools easily accessible but out of the way.

**A. Primary Navigation (Top Level - Easiest Effort)**
- **Filter:** `categories` (e.g., Geopolitics, Economy, Security)
- **Why:** This answers "What do I want to read right now?" It is the most standard user intent and should remain as highly visible pill navigation at the top of the feed.

**B. Impactful Discovery Hooks (The Widgets)**
- **Filters Driven:** `sourceOrigin` and `biasGroup`
- **Why:** These provide the biggest "Aha!" moment for a geopolitical aggregator. 
- **Execution:** Instead of hiding these in a dropdown, use the **Analytics Widgets** (e.g., `BiasDistributionWidget` or a `SourceOriginWidget`) to visually highlight the perspective gap. If a user sees a chart showing "80% of your feed is Western Media," clicking that chart should act as a quick-filter to instantly show the 20% Non-Western media. This turns a filter into an interactive discovery tool.

**C. Analytical Refinement (The Filter Popover)**
- **Filters:** `sourceType` (State vs. Commercial), `coverageScope` (Global vs. Local), and manual `biasGroup` selection.
- **Why:** These are advanced tools for users who want to dig deep (e.g., "I want to see how State Media is reporting this"). They should live in the existing **Filters Popover**. This keeps the main UI clean while offering immense power for analysts.

### 2. Dashboard & Analytics Widgets
- [ ] **BiasDistributionWidget:** Refactor to group articles dynamically by the new `biasGroup` field from the database. Make the chart clickable to quick-filter the feed.
- [ ] **PerspectiveWidget:** Enhance to cross-reference `sourceOrigin` against `sentimentScore` to visualize the "Perspective Gap" on specific clustered events.
- [ ] **EventClustersWidget:** Ensure that when a user clicks on a story cluster, the UI clearly breaks down the reporting by the Publisher's Identity metadata.

### 3. Article Cards & Details
- [ ] **ArticleCard:** Add visual badges or colored indicators representing the `biasGroup` (e.g., colored dots or pills). This provides immediate visual cues about "Who is talking" as the user scrolls.
- [ ] **ArticleDetailsModal / Story Pages:** Expand the "Based in..." section to fully display the Publisher's Identity (Origin, Country, Type, Bias Group, Coverage Scope).

## Domain-Specific Entity Extraction (Soft Power vs. Hard Power)

As of the latest architecture updates, the NLP pipeline (Stage 2) dynamically alters its extraction targets based on the domain (category) of the article.

*   **Hard News** (`geopolitics`, `economy`, `security`, etc.): Extracts `PERSON`, `ORG`, `GPE`, and `LOC`.
*   **Soft News** (`lifestyle`, `entertainment`, `sports`, etc.): Extracts `PERSON`, `ORG`, `PRODUCT`, `EVENT`, `WORK_OF_ART`, and `FAC`.

This allows us to track "Consumerism-driven political influence" and cultural soft power. For example, catching a trending `PRODUCT` (e.g., TikTok, Tesla) within an entertainment article.

### Frontend Implications & Inconsistencies
*   **Mapping Dependencies:** Currently, frontend map widgets rely heavily on `GPE` and `LOC`. Soft news articles will rarely have these entities extracted. **If a map widget assumes every clustered story has geographic coordinates, it will crash or render blank for soft news.**
*   **Presentation Ideas (TODO):** We should build a **"Cultural Exports / Soft Power" Widget** for the dashboard. Instead of mapping coordinates, this widget would track the velocity of specific `PRODUCT` or `EVENT` entities across global feeds to measure cultural influence.

> [!NOTE] 
> **Future Architecture Consideration:**
> As we potentially shift the enrichment architecture (e.g., moving to a Python microservice or local NLP to reduce LLM costs), the way these metadata fields are populated might change (e.g., faster, synchronous tagging vs. async LLM tagging). We should periodically revisit this frontend UX strategy to ensure the UI gracefully handles any delays in metadata processing or changes in how Story Clusters are formed.
